# T1-98 — Basic financial source Q&A (P1-24)

## Delivered scope

AI Intelligence now owns a bounded LOCAL/CI Q&A journey at Financial Q&A. A configured LLM interprets the question into a lexical retrieval plan, Search finds up to 20 candidate financial records, and AI Intelligence independently rehydrates Financial Profile facts/provenance and Evidence references. Derived search summaries are never financial truth. A second LLM pass selects up to ten canonical claims to explain the matching source records. The server rejects invented IDs, duplicate claims, contradictory states, extra fields and free-form financial assertions. Displayed amounts come verbatim from owner facts; model output cannot change them. This is genuine model-assisted retrieval and claim selection, with deterministic rendering, not an autonomous advisor.

The first implementation supports questions and summaries about matching financial source records. It explicitly returns insufficient information or unsupported scope for calculations, advice, predictions and verified balances/coverage/tax claims. It does not implement raw document-content interpretation, integrated rules execution, complete inventory summaries, advanced recommendations or semantic retrieval. The existing Net worth journey remains the supported separate deterministic calculation. Therefore P1-24 advances Pending to **Partial**, not Complete; MON-AI-001/003/009 and AIG-001/002 are partially implemented, not closed. OD-11 remains open for model/prompt/grounding/evaluation approval before UAT and production. No approved provider/model/notice is fabricated.

## Boundaries and audit

AI Intelligence owns orchestration and the AI response record. Integration Gateway alone calls the operator-configured HTTPS Chat Completions endpoint. Only the question and canonical source claim descriptions/amounts are sent externally; tenant/customer IDs, provenance IDs, document identifiers, session credentials and API credentials are not prompt content. API credentials are server-side, redirects/proxies disabled, provider bodies bounded and sensitive requests excluded from HTTP tracing. There are no tools, client-selected URLs, executable formulas or model-selected customer scope.

Current C&I session, ready active customer ownership and Self access are checked for AI analysis, Search, Financial Profile read and Evidence read. Source owners enforce their own contracts. Current subject/customer versions are compared before and after generation. Provider settings and published notice form a revision; explicit per-question permission must match it. Changing question or provider settings clears UI permission. React context changes remount and abort the previous journey, preventing late responses from entering a new session.

An AES-GCM encrypted LOCAL/CI file retains question, timestamp, provider model versions, fixed prompt version, configuration revision, permission notice, search record IDs, retrieved canonical facts/revisions/provenance/document versions, model selections and final answer. Atomic replacement, an exclusive file lease and process serialization protect writes. Attempts are checkpointed **before** provider spend: identical operation retries replay without more calls; changed payloads conflict. Failed/interrupted attempts remain NOT_COMPLETED and require a new submission to spend again. Limits: five attempts per customer/actor per minute, 1,000 retained attempts per customer/actor, 10,000 overall and a 32 MiB encrypted-store ceiling. No silent history eviction. Latest 20 attempts are shown; every history read rechecks source access and exact historical fact revisions. Historical answers are labelled as snapshots, not live balances. Distributed production storage, retention administration, export and key custody are not claimed.

## Onboarding and access configuration

External inputs remain optional. Use `-AiModelConfigurationFile <protected-json>` with the existing onboarding Prepare/Start flow, re-supplying it whenever configuration is regenerated. The JSON is keyed by T001/T002; each configured tenant supplies `Endpoint` (full HTTPS Chat Completions URL without query/userinfo/fragment), `ApiKey`, `Model`, `ProviderLabel`, and operator-published `Notice`. Use a compatible model supporting JSON mode and the configured completion budget; compatibility must be tested against the selected provider. No default provider, model or legal notice is invented. Missing configuration produces an explicit setup state rather than preventing organization activation.

Generated provider secrets go only to Integration Gateway. AI Intelligence receives only the internal workload token and its separate financialQaProtection key. Preserve that key and the drive-data volume's financial-qa directory together. The existing access catalog already contains resource-scoped ai-intelligence.analysis.execute and default-permission-ai-execute. Default Access Pack 2.5 is unchanged: the administrator explicitly grants that existing permission to the intended customer role/resource using the reviewed access-management flow, alongside Search/Profile/Evidence reads. No automatic grant to existing customers or advisor access is introduced. This configurable access step is shown in the customer UI.
