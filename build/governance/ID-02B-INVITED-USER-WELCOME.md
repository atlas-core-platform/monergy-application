# ID-02B — Invited-person LOCAL tester welcome entry (candidate)

**Scope:** An invited person, not the Organization Administrator, opens the Monergy sign-in page and chooses `Activate your invited account (LOCAL/UAT)`. An explicitly authorized tester can provide the protected LOCAL test capability in a transient form and request a genuine C&I single-use, five-minute welcome link for an existing pre-provisioned identity. The link opens the ID-01 welcome page, where that person creates their own password, then signs in normally. The system checks current AM membership/role and workspace access after authentication.

**Important boundary:** The LOCAL tester capability intentionally simulates mailbox access and is not genuine email-ownership proof. It grants the holder the ability to request links for eligible provisioned accounts. It must only be used by explicitly authorized test operators in disposable LOCAL profiles. Do not distribute the tester capability to general users or implement this public in Production. This phase does **not** create a true independently authenticated recipient inbox or invitation status lifecycle (ID-02C). The backend already enforces its Development-only guard and validates the capability before issuing any link; this UI does not bypass it.

**This unit adds:** `PersonaTesterWelcomeRequestEntry`, an invited-user-initiated action in tester-link mode of `PersonaCredentialEntry`, a route-specific return destination supplied by `WorkspaceEntry`, and focused React regression tests. A failed request does not reveal a link, and the tester capability is cleared from the form immediately. The capability travels only in the protected activation API request header; it is not persisted in URLs, localStorage or the admin's People screen. The welcome ticket is displayed only after an authorized backend response, and the existing `PersonaWelcomeEntry` strips its URL fragment before rendering.

**Next production-quality gates:** Source quality: full Customer Web ESLint zero errors/warnings, TypeScript, React entry and onboarding tests, build. LIVE LOCAL isolated profile: no tester secret returns 403, wrong secret returns 403, valid protected tester/identity gets welcome, expired/replayed tickets fail, activated credentials sign in only to authorized Customer/Advisor/Admin routes. Ensure unauthenticated email enumeration, tester-secret leakage, non-Development enablement and Administrator session impersonation are denied. Preserve all retained UAT profiles/data; no GitHub Actions.

**Next ID-02C:** Durable invitation delivery/receipt and status, independently recipient-bound delivery or tester mailbox isolation, resend/revocation, admin-visible nonsensitive status, and full activation audit. Keep production SMTP and genuine email verification separate.
