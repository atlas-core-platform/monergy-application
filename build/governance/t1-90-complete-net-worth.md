## Customer journey and input basis

Net Worth is available from workspace navigation, Financial information and the dashboard. Customers choose an as-of date and one currency, review all assets and debts, then save a review and calculate. Asset declarations cover cash, bank accounts, investments, property, vehicles and other assets; debts cover loans, credit cards and other liabilities. Each line requires a name and source explanation. Amount/date may remain unknown; no missing value is silently zero. Instructions require the customer's owned share/current values/outstanding balances, exclude insurance coverage, credit limits and original loan amounts, and require no double counting.

Existing exact-date/currency Investment, Property, Vehicle and Liability snapshots can be imported as complete bounded results; truncated, mismatched or malformed snapshots fail closed. Linked lines bind the exact owned saved record revision/name/current value or outstanding balance/currency/date and immutable financial fact, source revision, document version, provenance, evidence and reviewer lineage. Declarations are explicitly customer reported and unverified. They do not claim authoritative ownership or external valuation, or complete the broader Assets, Liabilities or Bank Accounts journeys.

Both asset and liability inventory completeness confirmations are explicit and reset after edits. Financial Rules produces totals only when the inventory is confirmed, all values/dates are known and comparable, and linked sources do not overlap. Missing values/dates, mixed dates/currencies, unconfirmed coverage or overlapping source records return INSUFFICIENT_DATA with actionable issues and all totals null. Empty inventories yield zero only after both explicit completeness confirmations. Negative net worth is supported. Money is exact decimal, serialized as fixed two-decimal strings; up to200 lines retain cents beyond JavaScript's safe integer-cent range. There is no FX, carry-forward, LLM arithmetic or financial advice.

The rule ID is monergy.net-worth, version1.0.0. Central configuration selects TOTAL_ASSETS_MINUS_TOTAL_LIABILITIES and this version; unknown definitions fail closed. Each calculation retains the definition hash, numeric semantics, full immutable reviewed input, totals/issues, actor, operation and time. The UI shows the formula, data basis and per-line source/version details. Paginated saved review and calculation history reopens exact past results. Updating creates a new review referring to the earlier position; it never rewrites history. The dashboard shows the latest saved result and its date/currency/basis, including an incomplete latest result rather than silently choosing an older total.

## Ownership, authorization and persistence

Product routes: GET/POST /product-api/v1/net-worth/positions, GET /positions/{positionId}; GET/POST /product-api/v1/net-worth/calculations, GET /calculations/{calculationId}. Owners expose matching /local/v1/customers/{customerId}/net-worth routes. Both histories use bounded cursor pagination. Current owned-customer/session and operator tenant binding apply. Self financial-profile.profile.read is required; inventory writes additionally require profile.update, calculations/history require existing financial-rules.calculation.execute, and linked document records require evidence.document.read. Read-only customers can inspect prior reviews/results with the applicable existing permissions.

Strict bounded JSON rejects missing, unknown, duplicate, null and malformed fields. Same-origin/no-store boundaries, current authority and matching subject/customer versions are checked before mutations and reconfirmed after reads/writes. Product independently reads the exact position, binds the entire receipt/result to customer, actor, operation, input and rule metadata, then reads back the exact saved object. Forged or stale receipts fail closed. Uncertain saves preserve identical input and operation IDs through close/reopen. Once the review is confirmed, retries continue only the same calculation. Customer/API/access changes hide old state and discard late responses.

Financial Profile migration0023 and Financial Rules migration0003 persist append-only scoped JSON records with operation uniqueness, transaction/advisory locks, immutable replay and cursor indexes. Runtime SELECT/INSERT grants exclude UPDATE/DELETE. In-memory adapters deep-clone stored and returned objects. Changed-payload/scoped operation reuse rejects. Calculation reads/history revalidate access to the exact underlying position. New physical restart/replay/source-lineage/scoped access/grant regressions compile; physical execution remains unverified.

Existing UAT service topology is reused. FinancialRules receives Monergy:NetWorth:Enabled=true, its existing FinancialProfileUrl, and explicit Formula/RuleVersion; ProductGateway receives the FinancialRulesUrl. No new service, provider, external package, Actions workflow or deployment is introduced. The lockfile adds only the existing Financial Rules project reference required by cross-owner tests.
