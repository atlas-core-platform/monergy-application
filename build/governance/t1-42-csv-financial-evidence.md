# T1-42 — Financial information CSV intake and candidate extraction

Base application: `41a43e3c60a67be3572acde868cc701b8f882250`. Requirements: Master §§9–12,13,41; AR-003 COV-011 / COV-014; M2-WS03-E01-F01 and M2-WS03-E02-F02, partial.

Customers can upload UTF-8 CSV and use a downloadable financial information template. Explicit columns are Category, Description, Amount, Currency, Date and Source; column order and header case may vary. Categories are the existing INCOME, EXPENSE, LOAN, ASSET, INVESTMENT, INSURANCE and TAX. Amount is a nonnegative invariant decimal (up to 28 characters to avoid decimal rounding), Currency is three ASCII letters, Date is yyyy-MM-dd, Description is at most 160 characters and unique within its category, Source is at most 140 characters. There must be 1–100 records within the existing 1 MB intake bound. Quoted commas, quotes, embedded newlines, CRLF and a UTF-8 BOM are supported. Unknown/duplicate/missing headers, extra columns, bad rows, unsupported categories, duplicate category/descriptions and excessive batches reject the entire extraction. The parser never executes spreadsheet formulas.

Evidence owns original bytes, media type, hash and exact customer/document/version identity. Document Intelligence verifies the original text hash, then copies explicit values into proposed facts with a source record reference. Parsing confidence 1 means exact field copying, not professional/source correctness; the active review calls this “Copied from CSV”. Candidate facts require the existing explicit customer review and Financial Profile normalization. No automatic mutation, financial calculation, inferred classification or bank-format guessing is added.

The current LOCAL execution policy, customer/session/tenant checks, workload separation and Job Management lifecycle are retained. Browser CSV with an empty or Windows spreadsheet MIME is normalized only when the filename ends in .csv; binary content still fails the Evidence UTF-8/signature checks. PDF/PNG/JPEG remain upload-only for this processor. No Excel workbook parser, OCR, production provider, production storage, antivirus claim or new permission is introduced.
