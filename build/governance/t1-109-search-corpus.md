# T1-109 — Complete document page traversal for search

Date: 2026-10-22. Removes the silent first-100-document cutoff from customer document search, retrieval context and explicit refresh. P1-10 and P1-23 remain Partial; this is corpus traversal, not completion of durable indexing or natural-language search.

Evidence's existing authorized ListCustomerEvidence contract adds optional AfterVersionId and NextVersionId fields. The owner resolves the cursor within the same customer and uses immutable created-time/version-ID keyset ordering, with a one-row lookahead. Reference and PostgreSQL adapters implement the same ordering. Existing consumers may still request one page. Missing, malformed and other-customer cursors reject without revealing another customer's documents. No new capability or alternate self-only endpoint is used; existing customer/advisor tenant, access and Consent checks apply on every owner request.

Search traverses every returned page before publishing its request-local projection. It rejects duplicate versions, malformed continuation, customer mismatch, later-page access denial and owner errors. It cannot return earlier pages as a successful partial result. Exact document-version/evidence references remain intact. An explicit 10,000-version resource bound fails with search.source.corpus-limit when further pages remain; it never truncates silently. Each request reads the current owner; no durable cache is introduced. Concurrent new uploads may require the next search, while immutable cursor ordering avoids offset drift.

No UI, provider configuration, package, schema or migration change. Physical PostgreSQL execution, live scanner/native OCR and authenticated full UAT remain unverified. Broader document classes, durable/background/knowledge indexing and natural-language retrieval remain open. No user decision is needed for this increment.
