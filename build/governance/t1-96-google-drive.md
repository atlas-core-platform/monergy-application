# T1-96 — Google Drive integration (P1-11)

## Delivered customer journey

Connections > Google Drive provides tenant configuration status, explicit customer permission, Google OAuth authorization in a separate window, account confirmation, identification of an existing folder to use as the Monergy source, bounded folder/file pages, exact-version import, refresh, import history and confirmed disconnect. Imports run through the existing Evidence malware scanner and document/version registration. Original Google files are never edited or deleted. Imported document review and processing reuse Documents; they do not automatically change Financial Profile data.

The server-side adapter uses fixed Google OAuth and Drive v3 endpoints. It requests drive.readonly because drive.file does not authorize arbitrary existing children of a selected folder. The customer explicitly sees that Google grants read/download access across the selected account, while Monergy limits imports to direct children of the selected folder. Google Docs exports, shortcuts, recursive folders and files beyond the existing supported 1 MiB intake are rejected. Supported formats are PDF, PNG, JPEG, text, CSV and XLSX. MON-SRC-007 still has the separate OneDrive gap.

## Owner and security boundaries

Integration Gateway owns provider configuration, tokens, connection/folder identity and import receipts. Current Customer & Identity ownership/setup and Access Management self-resource decisions are required for each operation. Consent Service separately owns 90-day document-import permission, exact connection/folder binding, revision/expiry/revocation and append-only evidence in migration0002. Provider authorization never substitutes for Monergy consent or Evidence upload authority. The selected tenant database retains provider-consent rows and narrow runtime grants.

OAuth state is random, ten-minute, one-use and bound to the initiating tenant/customer/actor/owner version/session and configuration revision. Callback consumption is durably checkpointed before code exchange. Current session, configuration and consent are checked again before activating tokens. Callback responses contain no code/token and are excluded from server request-start diagnostics and tracing. Tokens and state stay server-side in an AES-GCM encrypted LOCAL/CI owner file under a per-profile operator key. Atomic replacement, exclusive file lease and process serialization protect writes. An import intent is checkpointed before Evidence registration so uncertain retries retain the same identity/time. Disconnect checkpoints token erasure before external revocation, stops subsequent imports, and preserves import history. Unconfirmed revocation is shown explicitly with Google Account removal guidance.

Before download and again before registration, the flow checks current capability/ownership, consent revision, configuration revision, folder membership and provider file version. Downloads are bounded and compared with Google's size/checksum; Evidence independently computes SHA-256 and scans the actual bytes. Exact provider connection/file/version and Monergy document/version/hash remain in the encrypted import receipt. Product ingress emits minimized Audit request/result records without credentials or provider queries. New registered customers can use Evidence's immutable tenant binding for processing; conflicting static bindings and cross-tenant reads remain denied.

## Operator onboarding configuration

External dependencies remain optional for organization activation. For a named LOCAL onboarding profile, supply `-GoogleDriveConfigurationFile <protected-drive.json>` with `-EnableOnboarding` to `build/uat/Invoke-MonergyUat.ps1 -Action Prepare` or `Start`. Re-supply the file when regenerating the profile configuration. The JSON object is keyed by T001/T002. Each entry has ClientId, ClientSecret and RedirectUri. For the default port, register exactly `http://localhost:4173/connections-api/local/v1/google-drive/callback` with the organization's Google web OAuth client and enable the Drive API. The configured port must match. Google restricted-scope verification/testing-user rules apply to the operator's app. No real credentials are included in source.

Generated provider configuration is protected with the existing profile permissions and delivered only to Integration Gateway. A dedicated drive-data volume holds the encrypted store; preserve the matching profile encryption key and volume together. Do not replace a retained key. Customer tokens, secrets and raw provider endpoints are never editable fields in the browser. Not configured remains visible when no provider file is supplied. LOCAL/CI store bounds are 10,000 current customer connections and 1,000 import receipts per customer; distributed production storage/key custody remain separate.
